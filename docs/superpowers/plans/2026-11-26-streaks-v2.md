# Streaks-v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pure streak engine, exposed through FastAPI on Postgres + Floci S3. It produces the CSV, API, support view and the numbers in DECISIONS/TICKETS, all from one source.

**Architecture:**
- Raw events live in Postgres (deduped on `event_id`). S3 keeps the input files and every raw POST body.
- On every read, a pure engine recomputes days and the streak from the user's full event set.
- All rule values sit in `streaks/rules.py`.

**Tech Stack:** Python 3.12, FastAPI, Uvicorn, psycopg 3, boto3, pytest, Postgres 16, Floci (`floci/floci:latest`), Docker Compose.

**Spec:** `docs/superpowers/specs/2026-11-26-streaks-v2-design.md`. Read it first. §3 is the contract. Also read `CLAUDE.md` and `AGENTS.md`.

## Global Constraints

- Python 3.12. Dependencies are exactly: `fastapi`, `uvicorn`, `psycopg[binary]`, `boto3`, `pytest`, `httpx` (needed by the FastAPI TestClient). Nothing else without asking the user.
- **`engine`, `timeline` and `watches` are pure.** No DB, S3, HTTP, env reads or `datetime.now()`. Time comes in as `as_of`.
- All datetimes are tz-aware. A naive timestamp at the boundary is a parse error.
- Every rule value comes from `streaks/rules.py`. No literals like 120, 0.9, 48 or 168 anywhere else.
- Day codes (exact strings): `LEARNED`, `LEARNED_LATE_SYNC`, `TODAY_OPEN`, `PENDING`, `PROTECTED_OUTAGE`, `PROTECTED_FREEZE`, `SKIPPED_TRAVEL`, `BELOW_THRESHOLD`, `REJECTED_TAMPER`, `REJECTED_TOO_LATE`, `NO_ACTIVITY`.
- Status strings: `BROKEN`, `PENDING`, `ACTIVE`, `AT_RISK` (this precedence order).
- Expected outcomes are values. Parse errors are returned (`ParseError`), not raised.
- Names follow the naming cheatsheet: `get_`/`compose_`/`add_`/`is_`/`has_`, with units on constants (`_S`, `_H`).
- **No `git commit` unless the user has said so.** The "Checkpoint" steps commit only with that permission. Otherwise just run the tests.
- Run everything in Docker: `docker compose run --rm api pytest ...`. The local Python is 3.15, so don't rely on it.
- Time budget: the build ends by about 1:40 on the 3h clock. The minutes per task are targets. If a task overruns, cut its optional tests first.

## Review Focus

1. **Naive or garbage timestamps in POST** (`"2026-11-15 10:00"`, no offset). The item goes to `errors`, the rest of the batch goes in, nothing crashes. Tested in Task 7.
2. **Unknown `video_id` or `user_id` in POST.** Invalid item with a message. A watch with no known duration or publish time can't be judged. Tested in Task 7.
3. **Grader replays the same batch twice.** The second call reports every item as `duplicate`, and the streak is unchanged. Tested in Task 7.
4. **`watched_s` larger than the lesson.** The counted seconds are capped at `duration_s`, so one long watch can't hide a replay. Tested in Task 3.
5. **`as_of` before signup, or before 1 Nov.** No day rows, streak = carry-in or 0, no crash. Tested in Task 4.

### Task 2: Local day timeline (≈12 min)

**Files:**
- Create: `streaks/timeline.py`
- Test: `tests/test_timeline.py`

**Interfaces:**
- Consumes `User`, `Event` (`tz_change` only) and `rules.HISTORY_START_DATE`.
- Produces:
  - `DaySpan(date: date, start: datetime, end: datetime, length: timedelta)`, frozen, in `models.py`.
  - `get_day_spans(user: User, tz_changes: list[Event], as_of: datetime) -> list[DaySpan]`, sorted by date.
  - Covers every local date from `max(local signup date, HISTORY_START_DATE)` up to the local date of `as_of`. The last span's `end` may be after `as_of`.
  - `get_local_date(instant: datetime, tz: str) -> date`.

Algorithm (not fixed by the tests alone):
1. Build segments `[(tz, from_instant)]`. Start at `home_tz` from signup. Add one segment per `tz_change`, ordered by `client_ts`, switching to its `device_tz`.
2. Walk each segment `[a, b)` (the last one has `b = local midnight after as_of`) one local midnight at a time. Emit a piece `(date, max(a, midnight_d), min(b, midnight_d+1))`.
3. Merge pieces by date:
   - `start = min`, `end = max`, `length = sum of piece durations`.
   - Flying west repeats a date (u02), which merges two pieces into one. Flying east shortens one (u15).
4. Drop dates before the start date.

### Task 3: Dedupe and watches (≈12 min)

**Files:**
- Create: `streaks/watches.py`
- Test: `tests/test_watches.py`

**Interfaces:**
- Consumes `Event`, `Video` and the rules constants.
- Produces:
  - `dedupe_events(events: list[Event]) -> list[Event]`:
    - Pass 1 keeps one per `event_id`: the earliest `received_at`, tie broken by its own fields.
    - Pass 2 keeps one per `(user_id, event_type, video_id, client_ts)`: the earliest `received_at`, tie broken by the smallest `event_id`.
    - The output is sorted by `(client_ts, event_id)`. The same multiset in any order gives the same list.
  - `WatchVerdict(StrEnum)`: `TRUSTED`, `LATE`, `TAMPER_UNPUBLISHED`, `TAMPER_CLOCK_AHEAD`, `TOO_LATE`.
  - `Watch(event_id, video_id, day: date, started_at: datetime, counted_s: int, is_complete: bool, verdict: WatchVerdict)`, frozen, in `models.py`.
  - `compose_watches(events: list[Event], videos: dict[str, Video]) -> list[Watch]`:
    - Only `video_end` events with `watched_s > 0`.
    - `started_at = client_ts − watched_s`.
    - `day` = local date of `started_at` in `device_tz`.
    - `counted_s = min(watched_s, duration_s)`.
    - `is_complete = counted_s >= COMPLETION_RATIO × duration_s`.
    - Verdict order per spec §3.3: unpublished, then clock ahead, then too late, then late (> `LATE_SYNC_THRESHOLD_H`), else trusted.

### Task 4: Engine: days, freezes, streak (≈25 min)

**Files:**
- Create: `streaks/engine.py`
- Test: `tests/test_engine.py`

**Interfaces:**
- Consumes `get_day_spans`, `dedupe_events`, `compose_watches` and the models.
- Produces:
  - `DayRow(date: date, code: DayCode, counted_watch_s: int, detail: str)`, frozen.
  - `StreakResult(user_id, as_of, current_streak: int, status: StreakStatus, reason: str, days: list[DayRow], freezes_purchased: int, freezes_used: int, freezes_unused: int)`, frozen.
  - `compute_streak(user: User, events: list[Event], videos: dict[str,Video], outage: Outage, as_of: datetime) -> StreakResult`. These are the user's events only, unfiltered and undeduped.

Steps inside `compute_streak` (the order matters; it comes from spec §3.0 to §3.6):
1. Keep events with `received_at <= as_of`, then `dedupe_events`.
2. Build spans from the `tz_change` events. Build watches. Group watches by `day`.
   - A watch date with no span (a `device_tz` with no `tz_change`) gets a span built for it in that tz.
3. `latest_app_open` = the deduped `app_open` with the max `received_at`.
4. Classify each span **without freezes**, in spec §3.5 order 2 to 6:
   - Learned = a trusted or late watch with total `counted_s >= MIN_DAILY_WATCH_S`, or any `is_complete`.
   - `LEARNED_LATE_SYNC` if any counted watch is `LATE`.
   - The last span is `TODAY_OPEN` if not learned.
   - Outage applies if `user_id in affected_uids` and `[OUTAGE_START, OUTAGE_END)` overlaps `[span.start, span.end)`.
   - Short day: `span.length < MIN_DAY_LENGTH_H`.
   - Pending:
     - `as_of < span.end + PENDING_WINDOW_H`; or
     - `latest_app_open.received_at > span.end`, `meta.queue_depth > 0` and `as_of < span.end + MAX_OFFLINE_DELAY_H`.
   - Otherwise a final miss: `REJECTED_TAMPER` / `REJECTED_TOO_LATE` if the only watches that day are rejected; `BELOW_THRESHOLD` if a trusted watch exists; else `NO_ACTIVITY`.
5. Walk the days in date order, starting from `streak = user.streak_carry_in`:
   - learned: +1;
   - bridge or pending or today: unchanged;
   - final miss with `streak > 0` and pool > 0: becomes `PROTECTED_FREEZE`, pool −1;
   - other final miss: `streak = 0`.
   - Pool = `user.freeze_balance` + the count of `freeze_purchase` events.
   - `freeze_applied` events are ignored.
6. Status uses the precedence in Global Constraints.
7. Reason (wording is the builder's): one line naming the date and the code that matters most.
   - `BROKEN` → the last breaking day.
   - `PENDING` → the oldest pending day plus its deadline.
   - Otherwise the latest non-`LEARNED` day within 7 days, else "Learned N days in a row".
8. `freezes_used` counts `PROTECTED_FREEZE` days. `freezes_unused` = pool − used.
