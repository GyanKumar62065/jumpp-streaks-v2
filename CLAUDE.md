## 4. Architecture
```
 data/*.csv ──seed──▶ S3 (Floci) ──ingest──▶ Postgres (raw events, deduped)
 POST /events ──archive raw──▶ S3          ▲
             └──insert (idempotent)────────┘
                                           │ read all events for user
                                           ▼
                            engine.compute_days(events, as_of)   (pure)
                                           ▼
                            engine.compute_streak(days, as_of)   (pure)
                                           ▼
                  /streak   /days   /support/{id}   export_csv
```
- **S3 is the durable copy.** Input files and every raw POST body are stored there. Postgres can be rebuilt from S3.
- **Postgres stores raw events only.** Unique keys make inserts idempotent.
- **Engine is pure.** It recomputes from the full event set, so the result never depends on arrival order.
- **No cached streaks** in this build. Scaling notes go in the README (see §9).

## 5. Streak rules (decisions)
Full detail is in `docs/superpowers/specs/2026-11-26-streaks-v2-design.md` §3. Constants live in `streaks/rules.py`.

- **Learning day:** ≥ `MIN_DAILY_WATCH_S = 120` total, **or** one lesson finished (≥ `COMPLETION_RATIO = 0.9` of its duration).
- **Day of a watch:** the local date when it **started** (`video_end.client_ts − watched_s`), in `device_tz`.
- **Clock trust:** use `client_ts` only when:
  - `received_at - client_ts ≤ MAX_OFFLINE_DELAY = 7 days`;
  - `client_ts` is not after `received_at` (small skew allowed);
  - the video was published before `client_ts`.
  - Otherwise the event is rejected for streak purposes, with a reason.
- **Duplicates:** dedupe on `event_id`, then on (user, event_type, video_id, client_ts).
- **Order:** results come from the event set, never from arrival order.
- **Outage (9 Nov, 20:45 to 21:50 IST):** affected user + no lesson that day → **protected**.
- **Protected days bridge the streak and never add to it.** This covers freeze, outage and travel skip.
- **Travel:** the correct local day handles it. A local day shorter than `MIN_DAY_LENGTH_H = 12` because of a `tz_change` is `SKIPPED_TRAVEL` (bridge).
- **Unverifiable late sync (u13, u14):** accept, and flag for review. The ₹ case is in DECISIONS.
- **Pending:** a missed day is `PENDING` for `PENDING_WINDOW_H = 48`. No "lost streak" message while pending.
- **Freeze:** auto-used from the balance only after pending ends. Never offered while `queue_depth > 0`.
- **Old `freeze_applied` events are ignored.** A freeze on a day that later synced goes back to the pool.
- **Refund** only for a purchase made between a day's end and its late lesson arriving (u07).
- **Tampered days are never bridged by a freeze.**
- **Timezone timeline** = the last known `device_tz` from any event. All instants are UTC (DST-safe).

## 6. Reason codes
| Code | Meaning | Streak effect |
|---|---|---|
| `LEARNED` | Qualifying watch, on time | +1 |
| `LEARNED_LATE_SYNC` | Qualifying watch, synced late, within the cap | +1 (flagged) |
| `TODAY_OPEN` | Today (local), not learned yet | none |
| `PENDING` | No lesson yet, within 48h of day end | none yet |
| `PROTECTED_OUTAGE` | Our outage, no lesson | bridge |
| `PROTECTED_FREEZE` | Freeze applied to a miss | bridge |
| `SKIPPED_TRAVEL` | Calendar day skipped by timezone change | bridge |
| `BELOW_THRESHOLD` | Watched, but under the learning rule | break |
| `REJECTED_TAMPER` | Lesson "watched" before it was published | break |
| `REJECTED_TOO_LATE` | Synced beyond `MAX_OFFLINE_DELAY` | break |
| `NO_ACTIVITY` | Nothing watched | break |

## 8. Known data traps
- 3 duplicate event_ids. 3 resends with new ids (3.1.x).
- Late syncs: u03 (~38h), u06 (48h), u07 (15h), u13 and u14 (~24h, `queue_depth=3`).
- **u06 tampering:** "watched" v037 on 8 and 9 Nov. v037 was published on 10 Nov.
- u02: IST → LA. u15: LA → Auckland (crosses the date line).
- u04: swipes, under 40s a day from 6 Nov.
- u07: bought a ₹49 freeze for 7 Nov, then 7 Nov synced.
- u07: the phone reported `queue_depth=3` at 07:17, *before* the freeze sale at 09:02.
- u05: the lesson started 9 Nov 23:59:05 and ended 10 Nov 00:00:27.
- u10: 12 Nov = 101s of a 104s lesson (the completion rule saves it).
- u15: LA 10 Nov lasted only 10h40m before the jump to NZ 11 Nov.
- u08, u12: in the outage log. u09: signed up 13 Nov 23:50. u11: a `video_start` with no `video_end` on 11 Nov.
- Pooja's u08 = 314 breaks the "bridge, don't add" rule.

## 10. Commands
```
make up        # floci + postgres + seed + api (:8000), ready in ~10s on a warm cache
make test      # pytest in Docker (integration tests use the streaks_test DB)
make csv       # regenerate streaks_as_of_2026-11-15T1000IST.csv
make rebuild   # empty Postgres, replay inputs + raw POSTs from S3
```
- Floci is not published on a host port (4566 is often taken). Use `docker compose exec`.
